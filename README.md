# Cargo Auctions SPA

Тестовое задание: SPA для работы с грузовыми аукционами по OpenAPI-схеме (`openapi.auctions.v0.json`).

## Стек

React 18, TypeScript, Vite, TanStack Router (code-based route tree), TanStack Query, React Hook Form + Zod,
MSW (мок-сервер с in-memory стором, реально мутирующим состояние), Zustand (точечный UI-state: тосты,
мобильный drawer фильтров), Tailwind CSS (дизайн-система: токены цвета/теней/радиусов, адаптивная сетка),
Feature-Sliced Design (`app / pages / widgets / features / entities / shared`, с публичным API каждого слайса
и автоматической проверкой архитектуры через [steiger](https://github.com/feature-sliced/steiger)),
Playwright (e2e-тесты на ключевые пользовательские сценарии).

Готовая компонентная библиотека не подключалась — вместо этого на Tailwind собран небольшой набор
переиспользуемых примитивов (`shared/ui`: Button, Badge, Card, Input, Select, MultiSelect, Checkbox, Sheet,
Tabs, Tooltip, Pagination, EmptyState/ErrorState, Skeleton, Toast, набор line-иконок), поверх которых построен
единый визуальный язык (палитра, типографика, тени, скругления, состояния hover/focus/disabled).

## Запуск

```bash
npm install          # postinstall сам сгенерирует public/mockServiceWorker.js
npm run dev          # http://localhost:5173
npm run test         # vitest, юнит-тесты на чистую логику
npm run test:e2e     # playwright, e2e-сценарии на реальном dev-сервере + MSW (см. ниже)
npm run lint:fsd     # steiger — проверка соответствия архитектуры FSD
npm run build        # tsc -b && vite build
```

Если `postinstall` не отработал (например, npm install запускался с `--ignore-scripts`), выполните вручную:
`npx msw init public --save`. Перед первым запуском `npm run test:e2e` один раз поставьте браузер:
`npx playwright install --with-deps chromium`.

### Git-хуки (Husky)

В репозитории настроен [Husky](https://typicode.github.io/husky/): хук `pre-push` (`.husky/pre-push`) перед
каждым `git push` прогоняет `npm run lint:fsd` и `npm run test` (быстрые проверки — статический анализ и
юнит-тесты), чтобы в удалённую ветку не попадали изменения с нарушением архитектуры или падающими тестами.
E2E-тесты в хук намеренно не включены (требуют браузер и поднятия dev-сервера — секунды вместо
миллисекунд), они гоняются в CI. Хук ставится автоматически через `npm install` (скрипт `prepare` в
`package.json`), отдельная настройка не требуется.

### CI (GitHub Actions)

`.github/workflows/ci.yml` — на каждый `push` в любую ветку и на `pull_request` в `main`/`master` параллельно
запускает две джобы:

- **Test & Build** — `npm run lint:fsd` (архитектура FSD) → `npm run test` (юнит) → `npm run build` (typecheck
  `tsc -b` + production-сборка Vite).
- **E2E (Playwright)** — ставит браузер Chromium и прогоняет `npm run test:e2e` на поднятом самим Playwright
  dev-сервере; при падении в артефакты кладётся HTML-отчёт (`playwright-report/`) для разбора.

Это тот же набор проверок, что и в `pre-push`-хуке Husky (плюс e2e), только со стороны сервера — даже если
кто-то запушит с `--no-verify` или без Husky на своей машине, CI всё равно упадёт красным на PR.

## Структура (Feature-Sliced Design)

```
src/
  app/        — точка входа, роутер, глобальные провайдеры и стили (Tailwind base/utilities)
  pages/      — композиция экрана из виджетов (список / детальная / ставка)
  widgets/    — самостоятельные крупные блоки (шапка, список аукционов, детальная карточка)
  features/   — пользовательские сценарии: фильтры списка (+ мобильный drawer), установка ставки, история ставок
  entities/   — доменные сущности: auction, bet (типы, api-хуки, мапперы, ui-компоненты)
  shared/     — переиспользуемое: api-клиент, конфиг (enums/города), ui-дизайн-система, стор Zustand
  mocks/      — MSW handlers + in-memory "БД" аукционов и ставок
```

Все файлы React-компонентов имеют суффикс `*.component.tsx` (по требованию задания), включая набор
иконок (`shared/ui/icons.component.tsx`).

### Публичный API слайсов и правила импорта

Каждый бизнес-слайс (`entities/*`, `features/*`, `widgets/*`, `pages/*`) экспортирует наружу только через
собственный `index.ts` — остальные слои обязаны импортировать `@/entities/auction`, а не
`@/entities/auction/ui/AuctionCard.component` напрямую. Это даёт слайсу свободу менять внутреннюю структуру
(переименовать файл, перенести хук в другой сегмент), не трогая потребителей. `shared` — не слайс, а просто
переиспользуемая инфраструктура; там public API оформлен на уровне сегмента (`shared/ui`, `shared/api`,
`shared/config`, `shared/lib`, `shared/model`), а не по бизнес-смыслу.

Правило импортов между слоями стандартное для FSD (сверху вниз, без обратных и горизонтальных зависимостей
внутри слоя): `app → pages → widgets → features → entities → shared`. Соответствие проверяется автоматически
линтером [steiger](https://github.com/feature-sliced/steiger) (`npm run lint:fsd`, конфиг — `steiger.config.ts`),
подключённым и в `pre-push`, и в CI.

## Маршруты

- `/` — список аукционов, фильтры синхронизированы с URL search params (Zod-валидация с safe fallback)
- `/auctions/$auctionUuid` — детальная карточка, вкладки «Обзор» / «Ставки» через `?tab=`
- `/auctions/$auctionUuid/bet` — форма установки ставки, открывается напрямую по ссылке

## Дизайн и адаптив

- Десктоп: боковая панель фильтров (sticky) + сетка карточек 2–3 колонки в зависимости от ширины.
- Мобильный (< lg): фильтры скрыты за кнопкой с счётчиком активных фильтров, открываются в bottom-sheet;
  карточки — один столбец; детальная страница и форма ставки — одна колонка на всю ширину.
- Единая цветовая система статусов: тип аукциона, статус аукциона, торговый статус пользователя, ограничения
  DTO (`can_set_bet`, `hide_bets_history`, `hide_points_address_and_contacts`, `no_view_cargo_price`) — везде
  свои бейджи/иконки, чтобы это считывалось с одного взгляда на карточке и на детальной странице.
- Toast-уведомления (успех/ошибка) с авто-скрытием через 4.5 c и ручным закрытием.
- Фильтры с множественным выбором (тип аукциона, статус аукциона, мой торговый статус) — компонент
  `MultiSelect` (дропдаун с чекбоксами, счётчиком выбранного и кнопкой сброса), а не кликабельные чипы.
- Пагинация — переключатель «показывать по» (10/20/50/100), кнопки первой/последней страницы, окно номеров
  страниц с многоточием и прыжок на произвольную страницу по номеру (десктоп), компактный `N / M` на мобильном.
- Усечённый (`truncate`) текст в карточках списка (маршрут, груз) оборачивается в `Tooltip` — полное значение
  показывается всплывающей подсказкой при наведении/фокусе, ничего не обрезается «немо».

## E2E-тесты (Playwright)

`e2e/*.spec.ts` — реальный браузер (Chromium) поверх поднятого dev-сервера и «живого» MSW, без моков сети на
уровне теста. Покрыта основная бизнес-логика:

- **`auctions-list.spec.ts`** — загрузка списка и пагинация (переход между страницами меняет данные и URL),
  фильтр по `cargo_num` (ровно один результат), фильтр `is_available` (сужает выборку, пишется в URL),
  сброс фильтров до дефолтных search-параметров.
- **`auction-detail.spec.ts`** — переход из карточки списка в детальную страницу, переключение вкладок
  «Обзор»/«Ставки» с синхронизацией `?tab=`, состояние «не найдено» для несуществующего `auctionUuid`, 404
  для несуществующего маршрута.
- **`set-bet.spec.ts`** — ключевой сквозной сценарий: фильтрация до аукциона с `can_set_bet=true` и без своей
  ставки → отправка ставки → success-toast и экран «Ставка принята» → возврат на аукцион показывает
  обновлённые бейдж «Моя ставка», кнопку «Изменить ставку» и (если история не скрыта конкретным аукционом)
  запись в списке ставок — всё **без перезагрузки страницы**, то есть проверяется именно инвалидация React
  Query и мутация MSW-стора, а не просто отрисовка формы. Отдельно — клиентская Zod-валидация (`price <= 0`
  блокирует отправку без обращения к серверу) и disabled-состояние при `can_set_bet=false`.

Мок-данные (`mocks/db.ts`) генерируются с фиксированным сидом, поэтому тесты детерминированы: там, где
конкретный результат зависит от случайного поля мока, не связанного с проверяемым сценарием (например,
`hide_bets_history`), тест допускает оба легитимных исхода вместо жёсткой привязки к одному.

Запуск: `npm run test:e2e` (первый раз — `npx playwright install --with-deps chromium`). В CI — отдельная
джоба `E2E (Playwright)`, независимая от юнит-тестов.

## Что проверено вручную (дополнительно к автоматическим тестам, через Playwright-скрипты в headless-браузере)

- Список: загрузка (skeleton), пустой результат по несуществующему `cargo_num`, `refetch` после симулированной
  ошибки, пагинация вперёд/назад, prefetch детальной страницы по hover/focus на карточке (проверено через
  React Query Devtools — запрос детальной уходит до клика).
- Фильтры: применение и сброс, обновление URL, перезагрузка страницы с существующими search-параметрами,
  подстановка заведомо некорректных query-параметров (`?page=-5&auc_type=Foo`) — приложение не падает,
  используются fallback-значения; мобильный drawer открывается/закрывается, счётчик активных фильтров верный.
- Детальная страница: аукцион с `hide_points_address_and_contacts=true` (контакты и адрес скрыты),
  `hide_bets_history=true` (вкладка ставок показывает соответствующий empty-state), `can_set_bet=false`
  (кнопка ставки задизейблена, форма показывает пояснение вместо полей), `no_view_cargo_price=true` (цена
  груза скрыта иконкой вместо значения).
- Ставка (полный цикл end-to-end, включая клиентскую навигацию): открытие `/auctions/$id/bet` по прямой
  ссылке → отправка ставки в допустимом диапазоне `min/max/step` → success-toast → авто-редирект остаётся на
  странице с состоянием «Ставка принята» → переход обратно на аукцион показывает обновлённый статус
  (`NotParticipating` → `Leading`), новую текущую цену и бейдж «Моя ставка» — без ручного обновления страницы
  (инвалидация React Query сработала для list/detail/bets).
  Также проверены: `price <= 0`, `price` вне `min/max`, `price` не кратный `step` — клиент блокирует отправку
  на стороне формы; отдельно проверен путь мимо клиентской валидации (прямой вызов мутации) — MSW возвращает
  422 с `errors[]`, форма показывает эти сообщения.
- Ставки: список с несколькими участниками (цена с/без НДС, место в рейтинге, победитель, отменённая ставка
  с причиной отмены), количество участников/ставок, состояние «история скрыта» при `hide_bets_history`.
- 404: переход на несуществующий `auctionUuid` показывает EmptyState «Аукцион не найден» вместо краша.
- `npm run build` (tsc в строгом режиме + vite build) и `npm run test` — без ошибок.

## Известные баги исходной версии, найденные и исправленные в ходе ревью

- Неверный путь импорта типов в `entities/auction/lib/mappers.ts` (`./types` вместо `../model/types`) —
  ошибка была скрыта, так как `import type` стирается на этапе транспиляции и не всплывает в тестах, но
  ломала `tsc -b`.
- Несколько `<Link>` на `"/"` и `"/auctions/$auctionUuid"` не передавали обязательные (из-за `.catch()` в
  Zod-схеме) search-параметры — падало на этапе строгой типизации TanStack Router.
- Мок-генератор мог создать `min`, не лежащий на одной "сетке шага" с `current`/`start`, из-за чего
  автоподставленная в форму ставки "доступная цена" не проходила собственную же step-валидацию формы —
  выровнял генерацию цен в `mocks/db.ts`.
- Отменённые ставки в моках не получали `cancel_reason` — добавлен пул причин отмены.
- Место в рейтинге (`place`) ставок могло дублироваться (у вставленной "моей" ставки всегда стояло `1`
  без сдвига остальных) — добавлен пересчёт мест по фактическому порядку списка.
- На узкой карточке аукциона бейдж «Моя ставка» мог визуально наезжать на кнопку действия (`overflow`
  бейджа не был ограничен внутри flex-строки) — футер карточки разбит на отдельную строку «бейдж + кнопка»
  с `min-w-0`/`truncate` на бейдже и `shrink-0` на кнопке, наезд исключён на любой ширине.

## Ограничения

- MSW-стор живёт в памяти вкладки — обновление страницы (полная перезагрузка) сбрасывает сделанные ставки
  к исходному сгенерированному состоянию. Переходы внутри SPA (клиентская навигация) корректно сохраняют
  и отражают мутации.
- Фильтр `body_types`, `weight/volume` диапазоны, `customer`, `auction_ids` и часть менее приоритетных полей
  схемы не вынесены в UI — реализован обязательный минимальный список фильтров из задания (включая статус
  аукциона `statuses`, который в исходной версии отсутствовал).
- Один и тот же `AuctionListRequest` формируется из URL; синхронизация в `localStorage` не делалась — выбран
  вариант с URL search params (даёт шарибл-ссылки, что для аукционов важнее).
- E2E-тесты (`e2e/`) покрывают ключевые сценарии (список/фильтры/пагинация, детальная страница, полный цикл
  ставки), но не весь периметр UI — например, мобильный bottom-sheet фильтров и раскладка на узких экранах
  автотестами не покрыты, только вручную (см. выше).
